# konica-minolta-di1610-driver

Unofficial macOS and Linux driver for the **KONICA MINOLTA (Minolta) Dialta Di1610**, a GDI-only
laser printer/copier for which no Mac or Linux driver was ever released.

The printer protocol was reverse-engineered from the official Windows driver and is
documented in [docs/PROTOCOL.md](docs/PROTOCOL.md). The filter reproduces the Windows
driver's output byte-for-byte (`make test`).

> **Disclaimer.** This project is not affiliated with or endorsed by KONICA MINOLTA. It
> is provided as is, with no warranty. It was tested on **one** printer. A corrupted job
> only needs a power cycle of the printer, but use it at your own risk.

### Tested with

* **macOS 27.0.1** (build 26A434), Apple Silicon (M4 Pro), CUPS 2.3.4
* Apple clang 21, macOS SDK 27.0, Homebrew libusb 1.0.30, jbigkit 2.1 (downloaded by `make`)
* One Di1610 (USB ID `0686:400d`), connected **through a USB-C dock**
* Reference Windows driver: `Di1610bh160Vista32G108T100` (KM4 10.3.2.0, 2007)

Not tested: Intel Macs, older macOS releases, Di1610f, and the sibling models that share
the Windows driver (KONICA MINOLTA 160/160f, Konica 7416). Reports are welcome.
The **Di1610p** has a real PCL controller and does not need this driver: use a generic PCL driver.

## How it works

```
app ─► CUPS ─► rastertokm4 ─► socket://127.0.0.1:9101/ ─► launchd ─► km4usb ─► USB ─► Di1610
         (PDF → 8-bit gray)   (halftone + JBIG + KM4)       (localhost only)   (write-only)
```

* **`rastertokm4`**: the CUPS filter. It halftones the page, compresses it with JBIG1 and wraps it in the KM4 protocol.
* **`km4usb`**: sends the job to the printer over USB, writing only.

The printer is **not** attached to the standard macOS `usb://` backend. That backend polls
the printer's back channel; the Di1610 answers with USB STALLs, and any page that is still
being transferred while the paper moves prints as garbage (details in
[PROTOCOL.md](docs/PROTOCOL.md#transport)). `km4usb` only writes, and `launchd` starts it
for each job on a port that listens on `127.0.0.1` only.

## Install

### Prebuilt archives (no compiler needed)

Download the archive for your system from the
[Releases](https://github.com/svincio/konica-minolta-di1610-driver/releases) page:

| Archive | System |
|---|---|
| `macos-arm64` | Mac with Apple Silicon |
| `macos-x86_64` | Mac with Intel CPU |
| `linux-arm64` | Raspberry Pi (3B+ or later) with a **64-bit** OS, other ARM64 Linux |
| `linux-x86_64` | PC Linux |

Then, with the printer on and connected via USB:

```sh
tar -xzf konica-minolta-di1610-driver-*.tar.gz
cd konica-minolta-di1610-driver-*/
sudo sh macos/install.sh                               # macOS
sudo apt install cups && sudo sh linux/install.sh      # Linux (then reboot once, see below)
```

To uninstall: `sudo sh macos/install.sh uninstall` (or `linux/install.sh uninstall`).

* The macOS binaries are **not signed by Apple**. The install script removes the
  download-quarantine flag. They are built for macOS 13 or later, but only tested on macOS 27.
* The Linux binaries are built on Debian 12, so they run on Debian 12+ and on Raspberry Pi OS
  Bookworm and Trixie. They are 64-bit only: on a 32-bit OS, build from source.

### macOS from source

1. Install the Xcode Command Line Tools and Homebrew's libusb:
   ```sh
   xcode-select --install
   brew install libusb
   ```
2. Build (as your user, **not** with sudo) and optionally run the tests:
   ```sh
   git clone https://github.com/svincio/konica-minolta-di1610-driver.git
   cd konica-minolta-di1610-driver
   make
   make test        # optional, needs python3
   ```
3. Install:
   ```sh
   sudo make install
   ```
   This installs the files to `/Library/Printers/Di1610/`, installs the service
   `/Library/LaunchDaemons/io.github.svincio.di1610.km4usb.plist`, and creates the print
   queue **Di1610**. `lpadmin` will warn that *printer drivers are deprecated*: this is
   expected (see [Caveats](#caveats)).
4. Turn on the printer, connect it via USB and print a test page:
   ```sh
   echo "Hello from macOS" | lp -d Di1610      # or: lp -d Di1610 file.pdf
   ```

**Do not add the printer through System Settings → Printers.** macOS would create an
`usb://` queue, which uses the problematic backend. The queue made by `make install` is the
right one. If you had already created one, remove it in System Settings.

### Linux from source

Tested on a **Raspberry Pi 3B+** with **Raspberry Pi OS Lite 64-bit (Debian 13 trixie)**,
CUPS 2.4.10 and cups-filters 1.28.17. Other Debian-based distributions should work the same.

```sh
sudo apt install cups libcups2-dev git
git clone https://github.com/svincio/konica-minolta-di1610-driver.git
cd konica-minolta-di1610-driver
make && make test            # make test is optional
sudo make install            # printer on and connected via USB
sudo reboot                  # once, see below
```

On Linux the standard CUPS `usb://` backend is used: `make install` adds a USB quirk file
(`/usr/share/cups/usb/di1610.usb-quirks`, `unidir`) that turns off the back-channel reads.
The queue is named **Di1610**; `make install` uses `lpinfo` to find its `usb://` URI.

**Reboot once after installing CUPS.** `apt install cups` pulls in `colord`, which cannot
start until the system is rebooted; meanwhile every page waits for two 25 s D-Bus timeouts
(`gstoraster`, "Failed to send: org.freedesktop.DBus.Error.NoReply" in the CUPS log).
After the reboot a page takes a few seconds on a Pi 3B+.

### Uninstall

```sh
sudo make uninstall
```

## Caveats

* **A4 only.** On the test unit, Letter jobs end in a paper error, also from Windows. Any
  other page size is printed centred on A4.
* **If a job prints as garbage, or the printer hangs or shows `(01854) FMNEU.C`, switch the
  printer off and on again.** After a broken job the printer does not accept new data until
  it is power-cycled.
* **If the queue is paused** ("printer disabled", "unable to send data"): `cupsenable Di1610`.
  The queue uses `printer-error-policy=retry-job`, so this should be rare.
* **The USB port does not matter.** `km4usb` finds the Di1610 on any port. If the printer
  is off or disconnected, it waits up to 5 minutes for it before giving up.
* The printer is slow and briefly disappears from USB while warming up: this is normal.
* **PPD deprecation.** CUPS warns that PPD-based drivers are deprecated. They still work on
  CUPS 2.3 (macOS 27), but a future macOS could remove support.
* The device URI needs the `/` before the options (`socket://127.0.0.1:9101/?snmp=false`):
  without it `lpadmin` reports a *bad device URI*.
* The scanner part of the device is not supported (it uses a separate, TWAIN-only interface).

### Logs

* `/var/log/km4usb.log`: one `km4usb: sent N bytes` line per job, or the USB error.
* `/var/log/cups/error_log`: CUPS. Use `sudo cupsctl --debug-logging` to get more detail,
  and `sudo cupsctl --no-debug-logging` to turn it off again.

## Print quality

The engine spreads toner a lot (dot gain), so gray images are lightened with a tone curve
and printed with a clustered-dot screen. The defaults (`cluster`, gamma `1.8`) were chosen
with a calibration sheet on the test unit. If your prints are too dark or too light,
override them per job:

```sh
lp -d Di1610 -o km4-gamma=1.5 -o km4-dither=cluster file.pdf   # dither: cluster | bayer
```

To calibrate your unit, `python3 tools/taratura.py photo.jpg sheet.pdf` (needs Pillow)
makes a sheet with a 0–100 % wedge, a ramp, a photo and some text. Print it with a few
gamma values and keep the one where all steps are distinguishable. The defaults are
`DEFAULT_GAMMA` and `DEFAULT_DITHER` in `filter/rastertokm4.c`.

Text is never altered (pure black stays black).

## Development

| Path | Content |
|---|---|
| `filter/` | CUPS filter (portable C, CUPS + jbigkit) |
| `ppd/` | PPD (A4, 600/300 dpi, trays) |
| `macos/` | `km4usb` (libusb, write-only) and its launchd plist |
| `linux/` | CUPS USB quirk (`unidir`) |
| `docs/PROTOCOL.md` | KM4 protocol specification |
| `tests/` | byte-exact test against captures of the Windows driver |
| `tools/` | `km4pages.py` (split and decode a job), `km4dump.py`, `km4gen.py` (reference generator), `calib.py`, `taratura.py` |

New captures (for example other paper sizes) can be made in a Windows VM: install the
official driver, add a printer on the `FILE:` port, print, then inspect the result with
`python3 tools/km4pages.py <file>` (after `make test`, which builds the jbigkit tools).

## Italiano

Driver non ufficiale per macOS e Linux per la **KONICA MINOLTA (Minolta) Dialta Di1610**, una
stampante GDI per cui non è mai uscito un driver per Mac o Linux. Il protocollo è stato
ricavato dal driver Windows ufficiale. È stato provato su **macOS 27.0.1, Apple Silicon e
CUPS 2.3.4**, con **una sola** stampante collegata tramite dock USB-C.

**Archivi pronti, senza compilare**

Dalla pagina [Releases](https://github.com/svincio/konica-minolta-di1610-driver/releases) scarica
l'archivio giusto: `macos-arm64` (Mac Apple Silicon), `macos-x86_64` (Mac Intel),
`linux-arm64` (Raspberry Pi con sistema a 64 bit) o `linux-x86_64`. Poi:

```sh
tar -xzf konica-minolta-di1610-driver-*.tar.gz && cd konica-minolta-di1610-driver-*/
sudo sh macos/install.sh                               # macOS
sudo apt install cups && sudo sh linux/install.sh      # Linux, poi un riavvio
```

I binari macOS non sono firmati da Apple: lo script toglie la quarantena del download.

**Installazione dai sorgenti**

```sh
xcode-select --install && brew install libusb
git clone https://github.com/svincio/konica-minolta-di1610-driver.git && cd konica-minolta-di1610-driver
make && sudo make install
```

Si crea la coda **Di1610**. **Non** aggiungere la stampante da Impostazioni di Sistema →
Stampanti: userebbe il backend `usb://` di macOS, che corrompe le pagine grandi.

**Linux**

Provato su Raspberry Pi 3B+ con Raspberry Pi OS Lite 64 bit (Debian 13 trixie), CUPS 2.4.10.
Su Linux si usa il backend `usb://` standard di CUPS: `make install` aggiunge un file di
eccezioni USB (`unidir`) che disattiva la lettura del canale di ritorno.

```sh
sudo apt install cups libcups2-dev git
git clone https://github.com/svincio/konica-minolta-di1610-driver.git && cd konica-minolta-di1610-driver
make && sudo make install     # stampante accesa e collegata via USB
sudo reboot                   # una volta: senza, colord fa attendere ~50 s a pagina
```

**Accortezze**

* **Solo A4.** Con Letter la stampante di prova va in errore, anche da Windows.
* **Stampa rovinata, stampante bloccata o errore `(01854) FMNEU.C`:** spegnere e riaccendere la stampante.
* **Coda in pausa:** `cupsenable Di1610`.
* **Avviso "driver obsoleti" di `lpadmin`:** è normale. I PPD funzionano ancora su CUPS 2.3, ma un futuro macOS potrebbe toglierli.
* **Foto troppo scure o troppo chiare:** si regolano per singola stampa con `lp -o km4-gamma=1.5` (default 1.8, valori più alti schiariscono).
* **Registri:** `/var/log/km4usb.log` e `/var/log/cups/error_log`.
* **Disinstallazione:** `sudo make uninstall`.
